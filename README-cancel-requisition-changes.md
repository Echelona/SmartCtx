# สรุปการแก้ไข: ยกเลิกใบเบิก (cancelRequisition) — realtime sync + ยืนยันรหัสผ่าน + audit log

## ไฟล์ที่แก้ (รวมอยู่ในชุดนี้)

| ไฟล์ | สิ่งที่แก้ |
|---|---|
| `stock.db.js` | `verifyPassword()` เทียบรหัสผ่านแบบ timing-safe · `cancelRequisition()` เช็ค `CANCEL_REQ_PASSWORD` แยกจากรหัส login · เขียน `cancelled_by`/`cancelled_at` · migration เพิ่ม 2 คอลัมน์นี้อัตโนมัติตอนสตาร์ท (ปลอดภัยกับ DB เดิม ไม่ทับข้อมูล) · emit event `requisition:cancelled` |
| `stock.routes.js` | endpoint `/requisitions/:id/cancel` รับ `password` จาก body ส่งต่อพร้อมชื่อผู้ใช้จาก session (`getUser(req)`) · เพิ่ม rate limit (ผิดรหัสผ่านเกิน 5 ครั้งใน session เดียวกัน ล็อก 5 นาที) |
| `stock.page.js` | เปลี่ยนจาก `prompt()` เป็น modal พร้อม `<input type="password">` (mask ตัวอักษร, error inline, เคลียร์ค่าออกจาก DOM หลังใช้) · แสดงผู้ยกเลิก/เวลาที่ยกเลิกในรายละเอียดใบเบิก |
| `procurement.page.js` | รับ event `requisition:cancelled` แบบ realtime ผ่าน socket.io — ถ้าใบที่ถูกยกเลิกตรงกับแถวที่กำลังเปิดฟอร์มจัดส่งค้างอยู่ จะปิดฟอร์มพร้อมแจ้งเตือนทันที กันกดส่งไปแล้วเจอ error · แสดงผู้ยกเลิก/เวลาที่ยกเลิกในหน้ารายละเอียด (read-only) |
| `server.js` | เพิ่ม `'requisition:cancelled'` เข้า whitelist event ที่ bridge จาก eventBus ไปยัง socket.io |
| `procurement.db.js`, `procurement.routes.js` | ไม่ต้องแก้ไข — รวมมาในชุดเพื่อ reference/เทียบเคียงเท่านั้น (query กรอง `status != 'cancelled'` ถูกต้องอยู่แล้ว และ `SELECT *` ได้คอลัมน์ audit ใหม่มาอัตโนมัติ) |

## สิ่งที่ต้องทำเองเพิ่มนอกเหนือจากไฟล์เหล่านี้

**1) เพิ่มตัวแปรใน `.env` ของเซิร์ฟเวอร์จริง** (ไม่ได้แนบไฟล์ `.env` มาให้ เพราะเป็นไฟล์ secret เฉพาะเครื่อง ไม่ควรส่งต่อ/แชร์เป็นไฟล์):

```
CANCEL_REQ_PASSWORD=admin387
```

⚠️ **`admin387` ที่ระบุไว้ระหว่างสนทนานี้ถือว่าหลุดเข้า log การสนทนาไปแล้ว** — แนะนำให้ใช้เป็นค่าชั่วคราวระหว่างทดสอบเท่านั้น แล้ว**เปลี่ยนเป็นรหัสผ่านที่คาดเดายากกว่านี้ก่อน deploy ใช้งานจริง** (สุ่มยาว ไม่ใช่คำ+ตัวเลขสั้นๆ)

**2) รีสตาร์ท server หลัง deploy** — เพื่อให้ migration คอลัมน์ `cancelled_by`/`cancelled_at` รันตอนสตาร์ท (ทำครั้งเดียว ปลอดภัยกับข้อมูลเดิม)

## ลำดับทดสอบที่แนะนำ

1. รีสตาร์ท server (migration รัน)
2. ล็อกอินฝั่งคลังเคมีบำบัด (1.2) → สร้างใบเบิกทดสอบ
3. เปิดอีกแท็บ ล็อกอินฝั่งงานจัดซื้อ (1.1) → เปิดดูรายละเอียด/ฟอร์มจัดส่งของใบเบิกเดียวกันค้างไว้
4. กลับไปแท็บฝั่งคลัง → กดยกเลิกใบเบิกนั้น → ลองกรอกรหัสผ่านผิดก่อน (ควรเห็น error ใน modal, ลองผิดครบ 5 ครั้งควรโดนล็อก 5 นาที) → กรอกรหัสถูก (`CANCEL_REQ_PASSWORD` ใน `.env`)
5. เช็คว่าแท็บฝั่งจัดซื้อปิดฟอร์มเองพร้อม toast แจ้งเตือนทันที (ไม่ต้อง refresh มือ) และเห็นชื่อผู้ยกเลิก/เวลาที่ยกเลิกในรายละเอียด
